## 1. Резюме

Инструмент/процесс, который еженедельно собирает открытые вакансии по специальности **HR-менеджер** (и смежным ролям) из всех доступных источников в **Алматы** и **Астане**, группирует их по отраслям и компаниям, и выдаёт пользователю готовый список новых вакансий + рекомендации, куда откликаться в первую очередь — так, чтобы ни одна релевантная вакансия не осталась незамеченной.

MVP уже реализован в виде Excel-трекера (`Мониторинг_вакансий_HR_Алматы_Астана.xlsx`) с настроенными параметрами поиска, списком компаний по отраслям и еженедельным журналом вакансий. Этот документ описывает требования к продукту как таковому — включая целевое состояние, где часть процесса автоматизирована.

---

## 2. Проблема

Выпускник по специальности HR-менеджер ищет первую работу в двух городах (Алматы, Астана) и сталкивается с тем, что:

- Вакансии рассеяны по множеству источников (агрегаторы, госпортал, LinkedIn, Telegram/Instagram, карьерные страницы компаний), и ни один источник не покрывает 100% рынка.
- Одна и та же роль называется по-разному (HR-менеджер, HR generalist, менеджер по персоналу, специалист по подбору персонала и т.д.), из-за чего поиск по одному ключевому слову пропускает часть вакансий.
- Проверка всех источников вручную каждый день нерациональна по времени.
- Нет единого места, где видно: что нового появилось за неделю, по каким вакансиям уже был отклик, и какой статус по каждой.

## 3. Цели и метрики успеха

| Цель | Метрика |
|---|---|
| Не пропускать релевантные вакансии | ≥ 90% вакансий, найденных при ручной сверке за неделю, уже присутствуют в системе к моменту сверки |
| Снизить трудозатраты пользователя | ≤ 30 минут в неделю на весь цикл мониторинга |
| Увеличить число откликов | ≥ 5–10 релевантных откликов в неделю (при наличии подходящих вакансий) |
| Прозрачность воронки | 100% вакансий в трекере имеют актуальный статус (Новая / В работе / Отклик отправлен / Собеседование / Отказ / Оффер) |

## 4. Целевой пользователь

Выпускник вуза по специальности «Управление персоналом / HR», ищущий позицию уровня junior/entry (HR-менеджер, HR-специалист, рекрутер) в Алматы или Астане, без коммерческого опыта или с минимальным опытом (стажировки).

## 5. Границы (Scope)

### В скоуп
- Поиск вакансий по ролям HR-направления (junior/entry level) в двух городах: Алматы, Астана.
- Агрегация из внешних источников (агрегаторы вакансий, госпортал, LinkedIn, соцсети, карьерные страницы компаний).
- Еженедельная периодичность обновления.
- Группировка по отраслям и компаниям.
- Ведение статусов отклика (базовый ATS-трекер).
- Рекомендации: что приоритизировать, какие компании/вакансии стоит проверить в первую очередь.

### Вне скоупа (для v1)
- Автоматическая подача откликов / автозаполнение форм на сайтах вакансий.
- Анализ вакансий вне Алматы/Астаны.
- Роли выше junior/middle уровня.
- Интеграция с ATS-системами работодателей.
- Гарантия полного покрытия рынка (100% источников не существует технически).

## 6. Функциональные требования

### 6.1 Управление источниками
- Система должна поддерживать список источников: **hh.kz** (almaty.hh.kz, astana.hh.kz), **enbek.kz**, **rabota.kz**, **ГородРабот.kz**, **LinkedIn**, Telegram/Instagram-каналы, карьерные страницы компаний, **Google Alerts**.
- Для каждого источника должен быть настроен способ получения обновлений без ручного захода: RSS, email-подписка, push-уведомление, Job Alert.
- Источники должны быть расширяемы — пользователь может добавить новый источник без изменения структуры системы.

### 6.2 Ключевые слова и фильтры
- Поиск должен выполняться по расширенному набору синонимов роли: *HR-менеджер, HR generalist, менеджер по персоналу, специалист по подбору персонала, рекрутер, HR-специалист, HR business partner junior, Talent Acquisition Specialist, People Operations, HR Coordinator*.
- Обязательные фильтры: город (Алматы / Астана, раздельно), уровень опыта (без опыта / до 1 года), тип занятости (полная).
- Список ключевых слов должен быть редактируемым (список может устаревать или требовать уточнения).

### 6.3 Отраслевой и корпоративный охват
- Система должна поддерживать справочник «компания → отрасль → город» для точечной проверки карьерных страниц компаний, не публикующих вакансии на агрегаторах.
- Справочник должен быть расширяемым пользователем.

### 6.4 Еженедельный цикл мониторинга
- Раз в неделю (фиксированный день) система должна:
  1. Собрать новые вакансии по всем источникам за период с прошлой проверки.
  2. Отфильтровать дубликаты (одна вакансия может встретиться на нескольких агрегаторах).
  3. Записать новые вакансии в журнал со всеми атрибутами (компания, отрасль, город, источник, ссылка, дата публикации, зарплата).
  4. Отметить статус по умолчанию — «Новая».

### 6.5 Трекинг статусов отклика
- Каждая вакансия имеет статус: Новая → В работе → Отклик отправлен → Собеседование → Отказ / Оффер → Архив.
- Пользователь должен иметь возможность фильтровать и сортировать журнал по статусу, отрасли, городу, приоритету.

### 6.6 Рекомендации
- Система должна выделять вакансии с высоким приоритетом на основе: соответствия ключевым словам, отрасли из числа предпочитаемых пользователем, свежести публикации, наличия отметки «без опыта».
- Еженедельная сводка должна содержать краткий список «на что откликнуться в первую очередь».

---

## 7. Пользовательский поток (weekly flow)

1. Пользователь получает уведомления в течение недели (email/RSS/push) от источников с активной подпиской.
2. В назначенный день недели пользователь открывает трекер и вносит новые вакансии из уведомлений и из точечной проверки карьерных страниц компаний.
3. Пользователь присваивает приоритет и статус каждой новой вакансии.
4. Пользователь обновляет статусы вакансий из предыдущих недель.
5. Пользователь отправляет отклики по приоритетным вакансиям.

---

## 8. Нефункциональные требования

- **Язык**: интерфейс и данные — русский язык (с сохранением оригинальных английских названий должностей там, где это принято на рынке, напр. LinkedIn).
- **Стоимость**: решение v1 не должно требовать платных подписок (используются бесплатные тарифы источников).
- **Приватность**: система не должна передавать персональные данные пользователя (резюме, контакты) в сторонние сервисы автоматизации без явного действия пользователя.
- **Надёжность**: отсутствие единой точки отказа — если один источник недоступен, остальные продолжают работать.

## 9. Текущая реализация (v1 — MVP)

Реализовано как Excel-файл (`Мониторинг_вакансий_HR_Алматы_Астана.xlsx`) с листами:

| Лист | Назначение |
|---|---|
| Инструкция | Описание процесса и еженедельного ритуала |
| Параметры поиска | Настройки и способы подписки по каждому источнику |
| Компании по отраслям | Справочник компаний для прямой проверки карьерных страниц |
| Еженедельный мониторинг | Журнал вакансий со статусами, приоритетом и фильтрами |

Ограничения текущей реализации: сбор новых вакансий и заполнение журнала выполняются пользователем вручную на основе присланных уведомлений — автоматического парсинга и записи пока нет.

## 10. Дальнейшее развитие (roadmap)

| Этап | Описание |
|---|---|
| **v1 (текущий)** | Ручной трекер в Excel + настроенные подписки/алерты на источниках |
| **v2** | Полуавтоматический сбор: скрипт/агент раз в неделю опрашивает публичные RSS/API источников (где доступны) и формирует черновик записей для проверки пользователем |
| **v3** | Дедупликация вакансий между источниками, авто-приоритизация по заданным критериям, еженедельная сводка в Telegram/email |
| **v4** | Расширение на другие города/роли по запросу пользователя, аналитика рынка (динамика зарплат, спроса по отраслям) |

## 11. Риски и допущения

- Не у всех источников есть публичный API/RSS — часть агрегации (Telegram/Instagram/карьерные страницы) не автоматизируется полностью в рамках v1–v2.
- Значительная часть вакансий дублируется между hh.kz и агрегаторами — требуется логика дедупликации, иначе журнал будет зашумлён.
- Изменение структуры сайтов-источников может сломать автоматизацию (риск для v2+).
- Полнота покрытия рынка не может быть гарантирована на 100% — часть вакансий закрывается по знакомству/без публикации.

## 12. Открытые вопросы

- Нужна ли автоматическая рассылка еженедельной сводки (напр. в Telegram-бот) уже на этапе v2, или ручного открытия Excel-файла достаточно?
- Стоит ли расширять список отраслей/компаний по обратной связи пользователя после первых 2–3 недель использования?
- Приоритетна ли интеграция с LinkedIn API (требует бизнес-доступа) или достаточно Job Alerts по email?
